3.在.env中_port结尾为相关接口地址，与host结合为完整的网址。

5.本项目使用sqlite作为数据库
6.不要将.env中的机密信息回显和硬编码到任何位置，包括注释。

3.数据分析，状态已完成
已实现 web 前端界面（新增 web 子命令，只读模式打开 sqlite，纯 Go net/http + embed 静态资源 + 原生 JS/SVG 图表，零外部依赖，单 exe 可跑）。

3.1 使用方式：双击 `start-web.bat`（推荐，交互式选择端口/是否同步，默认 8080+启用同步），或命令行运行 `ai-pixel-analysis web [-addr :8080] [-sync]`。关闭后台残留进程用 `stop-web.bat`。，浏览器访问 http://localhost:8080。不加载 .env（不接触加密凭据），数据库以 mode=ro 打开，驱动层禁止写入，落实"严禁增删改"。

3.2 四个分页（顶部 tab 切换，右上角可按账号筛选）：
- 总览：账号数、7D 总请求、分账收入合计、当前/上一小时分账收入、小时环比(vs上一小时)、小时同比(vs昨天同小时)、今日收入、今日时均收入；每账号一行含 7D请求/占比、账户计费(total_cost)、用户扣费(actual_cost)、分账收入、各同环比、最新余额。
- 分账收入：逐小时/按天收入趋势图（稀疏补0，横轴连续）、收入 Top 使用者(consumer_user_id)、Top 上游账户(account_id)。
- 用量分析：总请求/tokens/计费/实扣/均耗时卡片、按模型明细表、request_type/billing_mode/stream 分布、按天用量趋势+明细表(含毛利=分账收入-用户扣费)、单日24小时分布。
- 流水明细：按方向(credit/debit)/原因筛选、分页表格，含金额/余额/使用者/Key/账户/请求ID。

3.3 分析口径：时间字段为 RFC3339 含时区，sqlite substr(created_at,1,13) 取本地小时桶。小时同环比按**分钟对齐**：当前小时已过 N 分钟，则对比"上一小时前 N 分钟"与"昨天同小时前 N 分钟"（同口径，不拿整小时比零头）；环比=当前周期/紧邻上周期−1；同比=当前小时/昨天同一小时−1；分母为0显示"—"避免误导。今日时均=今日累计分账收入÷已过去小时数。

3.4 推荐分析维度及理由：分账收入趋势(时/天)——核心业务指标识别高峰与拐点；收入Top使用者/上游账户——定位头部贡献者指导运营；按模型用量——模型成本差异大需拆分；毛利(收入-扣费)——反映分账后净留存；请求类型/耗时——评估负载特征。

3.5 不分析的字段及原因：request_id/ref_id(逐条唯一，聚合无意义仅追溯用)；balance_after逐点(时点快照，按天采样已足够)；user_agent(与计费收入无直接关联)；first_token_ms(非流式为空样本缺失多聚合失真)；inbound_endpoint/group_id(取值单一区分度不足)。

4.实现数据增量更新，状态已完成
实现方式：`ai-pixel-analysis web -sync`（start-web.bat 已带 -sync）。分析接口保持只读；同步由独立 worker 用可写连接+解密会话执行，机密不回显。新增"数据同步"页签。

4.1 数据获取方案：同步前按 账号×数据类型×时间块 生成 SyncPlan。usage 按天切块、ledger 按周切块、汇总快照（stats/dashboard）整段一次（聚合接口，一次到位无需分页）。每块独立推进水位。

4.2 增量与跳过：sync_watermark 表记录每账号每类已覆盖到的最大 created_at；已覆盖右端 = max(水位, 已有数据最大时间)，完全落入的块直接跳过（旧的手动 fetch 数据也能识别为已覆盖）。按 id upsert 幂等，中途停止下次从未覆盖处续传。

4.3 初始化按钮：库中无任何数据时可点，拉最近 3 天用于验证各功能；有数据后自动禁用。

4.4 更新按钮：纯增量——从覆盖右端（水位/已有数据最大时间）更新到按下时刻的前一分钟，不补历史。
   "回填最近30天"是单独按钮/任务（trigger=backfill），用于首次拉历史或补大段缺失，与增量更新分离。

4.5 自动同步：勾选"每分钟自动同步"后，运行期间每分钟增量同步一次；开关持久化，重启保留。

4.6 平滑请求：单并发 + 固定约 1.2s/请求间隔（-sync-interval-ms 可调）。不并发打爆上游；30天初始化预估页数随抓取动态修正 ETA。

4.7 进度可视：页签内实时显示——总进度条、已完成/总块数、已拉页/条、正在同步的账号+类型+时间窗+当前页、本项与整体预计完成时间、被跳过的块、历史任务列表、各账号数据覆盖水位。

4.8 任务中断处理：进程重启时自动把仍停在 running/pending 的旧任务标记为 interrupted（进程已死不可能还在跑），避免历史任务永远显示 running 误导。数据为空时范围显示"无数据"而非零值时间。

4.9 数据自动刷新：SyncWorker 维护 data_version，每次同步结算+1 并经 /api/sync/status 暴露；前端每3s轻量轮询，版本一变即静默重载当前页数据（数据层 load，非整页刷新），无需手动刷新/切tab。

4.10 是否需要其他增量形式：


- 已包含且必要：手动更新、定时自动、初始化、按账号增量、断点续传、跳过已覆盖。
- 已加"回填最近30天"独立按钮：首次拉历史/补大段缺失用，与高频增量更新分离（避免误点大任务）。
- 未加"自定义区间回填"：固定30天已覆盖绝大多数回填场景；更精确的历史区间用命令行 fetch -start/-end。
- 未加 webhook/实时推送：上游无此能力，只能轮询，每分钟已是最细实用粒度。

5.关闭界面提醒，状态已完成

5.1 入口：右上角新增「关闭界面」按钮（主动点击完整弹窗）；直接关浏览器标签/刷新受浏览器安全限制只能给原生确认框，勾选「不再提醒」后按所选方式静默执行。
5.2 实现：前端关闭弹窗 + POST /api/lifecycle/close-pref（记录行为）+ POST /api/lifecycle/shutdown（优雅停机，仅接受本机回环地址）；服务经 http.Server.Shutdown 退出并 Close 同步 worker。选择存浏览器 localStorage，重启恢复默认。
